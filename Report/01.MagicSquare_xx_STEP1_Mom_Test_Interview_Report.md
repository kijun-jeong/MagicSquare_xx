## 3. Mom Test 워크북 (이 인터뷰만 근거)

### 3.1 페르소나

4×4 **부분 마방진**(빈칸 2개, 값 `1~16`, **10선** 합 34)을 과제·연습으로 손/코드로 다루는 **학습자**. 행·열은 맞추다 **대각선 확인을 늦게** 하면 숫자를 반복 바꾸며 시간을 쓰지만, 맞추면 만족하고 넘어가는 경향.

### 3.2 인터뷰 답변 (과거 사실 — 직접 인용)

- “빈칸 2개 넣고 행·열·대각선 합 맞췄는데 대각선 하나 빼먹어서 20분 날렸다.”
- “20분 동안 숫자를 바꿔 넣었고, 끝에야 대각선을 확인했더니 합이 34가 아니었다.”
- “다시 바꿔 1분 만에 확인해 전부 맞았고, 기분 좋아서 그냥 닫았다. 이후 비슷한 격자는 다루지 않았다.”

### 3.3 표면 문제 (금지 — 솔루션·기능 섞임)

아래는 인터뷰 중 **기록만** 하고 제품·스펙 방향으로 쓰지 않음.

| 표면 문제 (금지 예) | 왜 금지인가 |
|:---|:---|
| “**대각선 자동 검사 기능**이 있으면 좋겠다.” | 구현 항목으로 바로 연결 |
| “**SquareValidator**를 Control에 두면 된다.” | ECB 설계 = 솔루션 |
| “4×4 마방진 **Solver**가 필요하다.” | 기능·알고리즘 선행 |
| “**ECB/TDD로** MagicSquare를 만들면 된다.” | 방법론·프로젝트명 = 솔루션 |

### 3.4 진짜 문제 (한 문장)

> **행·열·대각선(10선) 규칙이 동시에 걸릴 때, 확인 순서가 고정되지 않아 대각선을 늦게 보면 숫자를 반복 바꾸며 시간을 쓰고, 맞춘 뒤에는 검증 절차를 다시 쓰지 않고 넘어간다.**

## 4. 관찰·모순 (인사이트)

| 관찰 | 시사점 |
|:---|:---|
| 대각선 **맨 마지막** 확인 → **20분** 소모 | 10선 중 **대각선 2개**가 실행 순서에서 빠지기 쉬움 |
| 20분 동안 **숫자만 반복 교체** | 오류 **국소화 없이** 탐색적 수정 |
| 재수정 후 **1분**에 전 축 확인·**전부 맞음** | 절차·순서가 잡히면 비용이 **급감** |
| 맞춘 뒤 **기분 좋아** 닫음, ECB 실습 **미완** 가능 | “성공”이 **검증 습관 고정**으로 이어지지 않음 |
| 이후 **비슷한 격자 없음** | 학습 루프(피드백 → 재연습) **단절** |

---

## 5. 후속 인터뷰·보완 질문

- ECB 분류 실습 목표가 있었는데 **닫은 이유**(시간·피로·완료 착각)를 더 구체화할 여지.
- **표면 문제 수집**: 응답자가 **스스로** 말한 “~ 있으면 좋겠다”류 문장은 이번 세션에 없음 — 필요 시 별도 세션.
- **행동 변화**: 이후 격자를 다루지 않았으므로, 대각선 우선 확인 등 **습관 변화**는 검증 불가.
