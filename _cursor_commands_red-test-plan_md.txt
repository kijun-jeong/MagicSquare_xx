## 트리거

사용자가 **`/red-test-plan`만** 입력해도 동작한다.  
추가 인자가 없으면 아래를 **자동 추출**한다.

| 추출 항목 | 우선순위 |
|:---|:---|
| **세션 주제** | 채팅 최근 턴 → 워크북 Report → PRD §1·§9 |
| **RED 묶음 / Test ID** | 채팅 명시 → `RED_TODO` 체크 항목 → PRD FR 매핑 |
| **Layer** | 채팅 `entity`/`boundary` → 없으면 **entity** (Logic Track 기본) |
| **Track** | Layer=entity → **Logic** · Layer=boundary → **UI** |

명시적 오버라이드 예: `Phase: red | Layer: entity | Track: Logic` · `이번 RED 묶음: D-LOC-01 (FR-LOC-01)`

---

## Phase 선언

응답 **첫 줄**에 반드시 쓴다:

```
Phase: red | Layer: {entity|boundary} | Track: {Logic|UI}
```

이어서 **이번 RED 묶음**을 한 줄로 적는다 (예: `RED 묶음: RED-1~RED-3 — validate_lines 대각선 첫 위반`).

| Rule | 내용 |
|:---|:---|

## 출력 4블록 (표 형식 필수)

아래 **4개 섹션을 순서대로** 표로 작성한다. 파일 생성 없이 **채팅 응답만**.

### 블록 1 — C2C (Rule 1~3)

1. **PRD FR 인용** — `docs/PRD.md`에서 해당 FR 문장·§번호 인용 (없으면 §합성 근거 표기)
2. **To-Do 1개** — 판단이 필요한 항목만 (`[ ]` 체크박스 1행)
3. **Test ID → Given / When / Then** 표

```markdown
### 1. C2C 추적 (Rule 1~3)

| Rule | 적용 |
|:---|:---|
| Rule 1 | … |
| Rule 2 | … |
| Rule 3 | … |

**PRD FR-… 인용**

| 출처 | 인용 |
|:---|:---|
| §… | … |

**To-Do (판단 1건)**

| 판단 | To-Do |
|:---|:---|
| … | [ ] … |

| Test ID | Given | When | Then |
|:---|:---|:---|:---|
| … | … | … | … |
```

### 블록 2 — Track 설계표

**Logic Track (Layer: entity)** — Track B:

| Test ID | 대상 함수 | Given→Then | Invariant | Expected RED Failure |
|:---|:---|:---|:---|:---|

- **Test ID**: `D-*` 또는 세션 RED-N (`RED-1` 등)
- **Invariant**: PRD 불변식·R-01~R-06·I-* 등
- **Expected RED Failure**: 구현 없을 때 기대 실패 (`ModuleNotFoundError`, `AssertionError`, stub `...` 등)

**UI Track (Layer: boundary)** — Track A:  
동일 커맨드에서 **Layer만 `boundary`로 바꾸면 재사용**한다. 표 컬럼:

| Test ID | Given | Then | Expected RED Failure |
|:---|:---|:---|:---|

예: `U-IN-01` · `grid=None` → `E003` · `ModuleNotFoundError`

### 블록 3 — 테스트 플랜

| 항목 | 내용 |
|:---|:---|
| **파일 경로** | 예: `tests/test_validate_lines.py` · `tests/entity/test_d_loc_01.py` |
| **test 함수명 후보** | RED 묶음당 1함수 권장 · 명명: `test_{test_id_snake}_{요지}` |
| **conftest 픽스처** | G0~G8 또는 `grid_g1` 등 — **데이터만**, 도메인 로직 없음 |
| **pytest 명령** | 노드 1개 지정 예: `python -m pytest tests/...::test_... -v` |
| **RED 묶음 범위** | 이번 턴에 설계하는 Test ID 목록 (1~3건, 동시 GREEN 금지) |

픽스처 격자 예시는 **주석·튜플만** (파일 생성 금지).

### 블록 4 — ECB·Mock 점검

| 점검 | Logic Track (entity) | UI Track (boundary) |
|:---|:---|:---|
| Domain Mock | **금지** — 실 import·실 호출 | Boundary는 presentation mock만 허용 범위는 PRD 따름 |
| E001~E005 emit | **entity에서 raise/return 금지** | boundary/control은 PRD 스토리별 |
| import 방향 | entity → control/boundary **금지** | boundary → entity 허용, 역방향 금지 |
| 10선·34 중복 | Boundary에 판정 로직 **금지** | Entity/Command 호출만 |
